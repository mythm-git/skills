# Punctuation and Formatting

Use punctuation and formatting because they improve meaning, not as decoration.

| Pattern | Review action | Preserve when |
|---|---|---|
| Em/en dashes, semicolons, colons, ellipses, parentheses | Replace only when simpler punctuation improves readability | grammar, quotations, technical notation, or established voice requires them |
| Arrows, checkmarks, emoji labels, separators | Remove when decorative and unnecessary | a product UI, checklist, brand style, or user request needs them |
| Bold, italics, headings, bullets | Keep only structure that improves scanning | Markdown, documentation, accessibility, or an explicit format requires them |
| Quotation marks | Keep only quoted or semantically necessary text | titles, terms under discussion, dialogue, or exact wording |

Never modify code, formulas, CLI commands, URLs, paths, tables, Markdown syntax, citations, or required templates merely for stylistic reasons. Preserve strict formatting exactly unless the user asks to alter it.

A plain paragraph is often right for a short message. A list or headings may be right for instructions, a comparison, or documentation. Review function, not symbol counts.
